# Единые типы расхождений — дизайн

## Цель

Сделать таблицу «Расхождения» одинаково понятной после программной и экспертной проверки, сохранив технические категории Claude внутри данных.

## Утверждённое поведение

- В таблице «Расхождения» семь колонок; колонка «Документ» отсутствует.
- Claude использует в `conclusion`, `title` и `reason` только пользовательские термины: «Нет у контрагента», «Нет у организации», «Разница в суммах», «Разница в датах», «Зеркальный КСФ», «Связь с начальным сальдо», «Требуется проверка».
- Техническая категория Claude сохраняется в JSON и независимо нормализуется интерфейсом:
  - `confirmed_missing` → сторона-зависимый `missing_in_counterparty` или `missing_in_company`;
  - `sign_difference` → `sign_mismatch`;
  - `amount_difference` → `amount_diff`;
  - `likely_date_pair` → `date_diff`;
  - `opening_balance_bridge` и `ambiguous` остаются отдельными типами.
- Кнопки фильтрации работают по нормализованному типу; экспертные дополнительные кнопки показываются только при наличии соответствующих строк.
- Термин «Зеркальный КСФ» используется во всём пользовательском интерфейсе вместо «Зеркальная КСФ».
- Строки-источники `opening_balance_bridge` на вкладке «Сравнение» имеют зелёную подсветку, а легенда содержит зелёное значение «Связь с начальным сальдо».

## Надёжность

Промпт снижает вероятность нестандартных формулировок Claude, но интерфейс не доверяет тексту модели и всегда строит тип, фильтр и цвет по машинной категории и подтверждённым ссылкам на строки.
