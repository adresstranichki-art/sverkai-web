# Экспертный анализ исходных Excel-файлов Claude

## Цель

Экспертный режим передаёт Claude два оригинальных файла `.xls`/`.xlsx` целиком и выбранные пользователем настройки сверки. Claude самостоятельно открывает книги, определяет структуру листов, организации, период, сальдо, операции и расхождения. Программные пары, рассчитанные сальдо и выводы стандартной сверки в экспертный запрос не передаются.

Существующая оптимизированная реализация v2 сохраняется в `expert_reconciliation_v2.py` вместе с отдельными тестами.

## Выбранный транспорт

Исходные файлы загружаются в Anthropic Files API и прикрепляются к одному запросу как `container_upload`. В Messages API включается `code_execution_20250825`, чтобы Claude мог открыть `.xls` и `.xlsx` установленными в контейнере библиотеками. Обычный `document`-блок для Excel не используется, потому что Anthropic его не поддерживает.

Текстовая часть запроса содержит только:

- соответствие `doc1`/`doc2` оригинальным именам файлов;
- пользовательские настройки `find_missing`, `find_amount_diff`, `find_sign_mismatch`, `find_date_diff`, `date_window_payment`, `date_window_delivery`, `min_amount`;
- правила анализа и JSON-схему результата.

Сырые ячейки, программные операции, стандартные расхождения и программные сальдо в текст запроса не дублируются.

## Анализ Claude

Промпт требует обязательно использовать Code Execution и до формирования ответа:

1. открыть оба файла;
2. перечислить все листы и проверить все заполненные области без ограничения количества строк;
3. учитывать положение ячеек, формулы и доступные значения;
4. самостоятельно найти заголовки, стороны учёта, период и сальдо;
5. сопоставить все операции с учётом пользовательских настроек;
6. не дублировать одну операцию в нескольких расхождениях;
7. вернуть только структурированный отчёт версии 3.

Результат сохраняет существующий UI-контракт `independent_expert`: `conclusion`, `confidence`, `balances`, `discrepancies`, `completeness` и `resolved_evidence`.

Разрешённые категории:

- `confirmed_missing`;
- `sign_difference`;
- `amount_difference`;
- `opening_balance_bridge`;
- `likely_date_pair`;
- `ambiguous`.

## Ссылки на источник

Claude ссылается на физические строки Excel идентификаторами `sN:rM`, где `N` — нулевой индекс листа в книге, `M` — нулевой индекс строки. Сервер локально строит индекс непустых строк исходных файлов и проверяет только существование ссылок. Бухгалтерские выводы и суммы Claude сервер не пересчитывает.

Если строка существует и распознана стандартным парсером, расхождение остаётся кликабельным и открывает её во вкладке «Сравнение». Если исходная строка не попала в стандартный разбор, расхождение показывается без перехода с предупреждением. Несуществующая ссылка не удаляет вывод, а получает пометку «Источник не найден».

## Безопасность и удаление

- Для каждой проверки используются новые загрузки Files API и новый контейнер.
- Идентификаторы файлов не кэшируются и не сохраняются в историю.
- Содержимое файлов, `file_id` и результаты Code Execution не записываются в журналы приложения.
- Каждый успешно загруженный файл удаляется через `DELETE /v1/files/{file_id}` в блоке очистки независимо от успеха анализа, ошибки второй загрузки, ошибки Messages API или неверного ответа.
- Ошибка удаления не скрывается: результат получает предупреждение `remote_file_cleanup_failed`.
- Временная папка Railway продолжает удаляться существующим `finally` обработчика `/api/reconcile`.
- API-ключ остаётся только в переменной окружения Railway.

Anthropic может сохранять данные контейнера Code Execution до 30 дней; немедленное удаление Files API не отменяет этот срок.

## Production-предупреждение

В существующем блоке `env-badge`:

- на `production`/`prod` всегда показывается точный текст: «Если загружаемые файлы содержат конфиденциальную информацию, рекомендуем перед отправкой обезличить данные.»;
- на остальных окружениях сохраняется текущая информация о стенде и версии.

Предупреждение находится перед карточками загрузки и не требует отдельного диалога.

## Ошибки

- Нет API-клиента: `api_key_required`.
- Исходный файл уже недоступен: `source_file_unavailable`.
- Ошибка загрузки: `file_upload_failed`.
- Ошибка вызова Claude возвращается безопасным именем типа ошибки без содержимого документа.
- `max_tokens`, `refusal` и неверная структура ответа не заменяют стандартную сверку.
- При любой ошибке экспертного режима пользователь продолжает видеть стандартный результат.

## Проверка

- Тест подтверждает загрузку двух оригинальных бинарных файлов, а не JSON ячеек.
- Тест проверяет `container_upload`, Files API beta и `code_execution_20250825`.
- Тест подтверждает передачу всех пользовательских настроек без результатов стандартной сверки.
- Отдельные тесты проверяют удаление после успеха, после ошибки второй загрузки и после ошибки Messages API.
- Тест проверяет предупреждение на production и сохранение индикатора на staging.
- Тесты ссылок, карточек Claude и архивной v2 остаются зелёными.
