# Экспертная сводка: компоновка, настройки и группировка

## Цель

Сделать независимый экспертный отчёт Claude компактным и предсказуемым: убрать дублирование в «Сводке», показывать названия организаций вместо `doc1`/`doc2`, учитывать выбранные пользователем настройки анализа и группировать расхождения по критичности.

## Границы изменений

Изменения относятся только к независимому экспертному режиму. Обычная сверка, выбор пары таблиц, переход из «Расхождений» в «Сравнение» и расчёт сальдо остаются без изменений. Выводы обычного алгоритма по-прежнему не передаются Claude.

## Верхняя часть «Сводки»

Для независимого экспертного режима существующий верхний ряд из четырёх статистических карточек удаляется. Вместо него наверху показывается единый двухколоночный блок:

- слева — три вертикальные карточки «Разница начального сальдо», «Движение периода» и «Разница конечного сальдо»;
- справа — зелёная карточка с кратким заключением Claude и уровнем уверенности;
- на узком экране правая карточка переносится под три расчётные карточки.

Значения трёх расчётных карточек по-прежнему вычисляет программа из извлечённых сальдо. Заключение и уверенность поступают из ответа Claude. Строка «Подтверждено / к проверке» в верхней части удаляется. Формула остаётся только в нижней карточке детализации, поэтому числа не дублируются.

Нижняя часть экспертного отчёта начинается с групп расхождений. Повторные заголовок, три карточки, заключение и формула из текущего большого блока удаляются.

Окно «Рекомендации и ограничения» удаляется. Поля `actions` и `limitations` также удаляются из контракта ответа Claude, чтобы не расходовать токены на невидимые данные.

## Названия организаций

При чтении документа программа извлекает названия сторон из шапки акта и связывает название с выбранной стороной таблицы. В экспертный payload для каждого документа добавляется `display_name`.

Claude получает явное правило:

- в `conclusion`, `title` и `reason` использовать `display_name` организации;
- не использовать технические обозначения `doc1`, `doc2`, `d1`, `d2` в пользовательском тексте;
- технические `side` и `row_id` сохранять только внутри `evidence`, чтобы переход к исходным строкам продолжал работать.

Если название нельзя надёжно извлечь, используется исходное имя файла. Claude не должен придумывать название.

## Передача настроек Claude

В экспертный payload добавляется объект `analysis_scope`:

- `find_missing`;
- `find_amount_diff`;
- `find_sign_mismatch`;
- `find_date_diff`;
- `date_window_payment`;
- `date_window_delivery`;
- `min_amount`.

Промпт объявляет этот объект обязательными границами анализа:

- при `find_missing=false` не формировать `confirmed_missing`;
- при `find_amount_diff=false` не формировать `amount_difference`;
- при `find_sign_mismatch=false` не формировать `sign_difference`;
- при `find_date_diff=false` не искать и не формировать `likely_date_pair`;
- окна оплат и поставок ограничивают допустимое расстояние между датами для `likely_date_pair` соответствующего вида;
- `min_amount` исключает меньшие расхождения из отчёта;
- `opening_balance_bridge` разрешён независимо от переключателей и минимальной суммы, поскольку объясняет начальное сальдо.

Программа не фильтрует результат Claude повторно по этим настройкам. Проверка существования ссылок evidence сохраняется, поскольку нужна для безопасной навигации. Существующая защита от ложного `confirmed_missing` работает только при `find_date_diff=true`; при отключённой проверке дат программа не создаёт категорию `likely_date_pair` самостоятельно. Эти проверки не используют выводы обычного алгоритма.

## Группировка расхождений

Промпт требует возвращать категории непрерывными группами в следующем порядке:

1. `confirmed_missing` — подтверждённое отсутствие;
2. `sign_difference` — разница направления;
3. `amount_difference` — разница суммы;
4. `opening_balance_bridge` — связь с начальным сальдо;
5. `likely_date_pair` — вероятная пара по датам;
6. `ambiguous` — требуется ручная проверка.

Внутри каждой группы элементы идут по убыванию абсолютного влияния на итог. Интерфейс отображает отдельный заголовок перед каждой непустой группой и использует тот же порядок категорий. Сортировка интерфейса меняет только представление, но не категории и выводы Claude.

Каждая строка сохраняет resolved evidence и остаётся кликабельной. Нажатие открывает вкладку «Сравнение» и подсвечивает соответствующие строки обоих документов, если ссылки удалось разрешить.

## Ошибки и запасные варианты

- Если экспертный анализ не выполнен, остаётся текущий обычный результат и показывается сообщение об ошибке экспертного режима.
- Если название стороны не найдено, используется имя файла.
- Если evidence не разрешён, вывод Claude сохраняется с предупреждением, но строка не получает ложную навигацию.
- Пустые группы в таблице не отображаются.

## Проверка

Реализация выполняется через тесты:

- payload содержит `analysis_scope` и извлечённые `display_name`;
- промпт запрещает технические названия в пользовательском тексте и задаёт порядок групп;
- схема ответа больше не требует `actions` и `limitations`;
- представление независимой «Сводки» не содержит старого ряда и окна рекомендаций;
- категории группируются в утверждённом порядке, внутри группы — по модулю влияния;
- переход из экспертного расхождения в «Сравнение» не регрессирует;
- интерфейс корректно складывается в одну колонку на узком экране;
- полный набор серверных и браузерных тестов проходит перед публикацией в staging.
